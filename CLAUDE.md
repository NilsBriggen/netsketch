# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

NetSketch: a from-scratch modernization of the Filius network-teaching app, rewritten in Rust + egui (eframe). The goal was to modernize the outdated tool and turn it into versatile software that also plans real home networks: Wi-Fi coverage, walls/floors, measurements, cost, power. There's also an Android companion app for on-site Wi-Fi surveys.

**Clean room:** nothing inside `/usr/share/filius/filius.jar` may be read: its files, folder and code. Work from the person's description and reference pictures only. `fls.rs` imports old `.fls` projects from the *saved file format* only (checked against a real Filius 2.4.1 save), not from the jar.

Locally this repository sits in a Craft Anything project folder (`../`). Its files there (`craft.json`, `feed.json`, `checks/`, `investigation.cany/`, `build-activity.log`, `usage.json`, reference pictures) are the build tool's state, not part of the repo. Don't hand-edit them.

## Commands

```bash
cargo run                                  # the desktop app
cargo test                                 # all unit tests (fast, no GUI)
cargo test fix_all_repairs                 # one test by name substring
cargo run -- --screenshot shots/now.png    # renders ~120 frames, saves a PNG, exits
```

The `--screenshot` mode is what the Craft Anything build checks use. It also turns autosave off. When the desktop gives no frames (screen off), run it on a virtual display: `env -u WAYLAND_DISPLAY xvfb-run -a -s "-screen 0 1920x1200x24" cargo run -- --screenshot shots/now.png`.

Android companion (`companion-android/`): `./build.sh` needs JDK 17+ and the Android SDK (platform 35, build-tools). It uses no Gradle: javac + aapt2 + d8 + apksigner. Its first step compiles the plain-Java parts (`PLAIN` in `build.sh`: `Survey`, `Link`, `T`, `Air` scan parsing, `Watch`, `Lan`, `Assistant`) with every test in `test/` on the host and **regenerates `sample.netsurvey`**. The Android-only parts are `MainActivity`, `Pages` (the Around you / Watch / Check-up / Devices tabs), `Scope` (scanning, RTT, the shared scan budget) and `WatchService` (foreground service of type location). The Rust test in `companion.rs` reads that file with `include_str!`, so a change to the phone's file format must be checked from both sides. Phone text goes through `T.t("English")` / `T.f(template, args)`; German is the table in `T.java` (a host check compares placeholders).

Releases: pushing a tag `v*` makes CI build the AppImage, MSI (WiX 5, `packaging/netsketch.wxs`), portable exe, macOS tarball and APK, and publish them with `.github/release-notes/<tag>.md` as the description. Write that file before tagging. The APK is signed with the `ANDROID_KEYSTORE` repo secret (base64 of the local `signing.keystore`).

## Architecture

The project is one binary crate, `src/`. The design has two halves:

- **Model (`Network`, in `net.rs`):** a plain, serde-serializable struct: devices, links, walls, floor plans, survey points, labels and settings. Its behaviour is split across files by topic, each adding its own `impl Network` block: `net.rs` (addressing, DHCP, problem checks, packet simulation, the terminal `exec`), `wifi.rs` (signal/path-loss model, channels, roaming, hardware presets), `stp.rs` (spanning tree), `issues.rs` (more checks plus one-click `Fix`es via `apply_fix`), `plan.rs` (coverage score, AP suggestion, `fix_all`), `extras.rs` (PoE, firewall, IPv6, guest VLAN, app traffic, device library), `more.rs` (resilience, power, time of day), `companion.rs` (phone measurements → pins/neighbours), `phone_link.rs` (live phone link). These files have no egui dependency and carry all the tests.
- **UI (`App`, in `main.rs`):** one egui app with modes Design / Simulate / Learn. It is likewise split into `impl App` blocks in `radio_ui.rs`, `ui_draw.rs`, `ui_extras.rs`, `ui_more.rs`, `ui_companion.rs`, `ui_shell.rs`, `ui_select.rs` and `ui_desk.rs`, which pull in `main.rs`'s imports, colour constants and types with `use super::*`. Layout:
  - **Top bar:** File menu, Design/Simulate, undo/redo, storeys, gear (language, look, shortcuts).
  - **Left rail of workspaces** (`ui_shell::Space`): Plan, Coverage, Measure, Check (problems, shopping, power, compare), Traffic (plus the packet log in Simulate), and Learn. In a workspace, `section()` draws plain headings (`ui_shell::FLAT`); elsewhere it draws fold-outs.
  - **Over the map:** a floating tool dock with the add-device palette, search and the Wi-Fi map switch, and zoom.
  - **Right panel:** only while something is selected. A device's panel has tabs (`DevTab`: General, Wi-Fi, Network, Security, Power and use) and each editor part checks `self.dev_tab`. Edits made in the panel become undo steps by themselves: `ui()` compares the selected thing's JSON before and after `inspector()` (`sel_copy`, `Before`), merging a burst on the same thing into one step.
  - **Device desktops (`ui_desk.rs`):** double-click a computer (or "Open desktop") for a window with its installed apps; several can be open (`App.desks`, per-desktop state in `App.desk`). The apps reuse `browser()` and `terminal()`; files, editor, mail client, firewall and the server apps (web, DNS, DHCP, mail, file sharing, printing) edit the device's own fields.
  - **Selection:** `sel` is the one in the panel; `extra` holds more (Shift+click, Shift+drag box). `ui_select.rs` moves, nudges, deletes, aligns, copies and pastes the whole selection; `tidy_selection()` drops `extra` when `sel` changes any other way.
  - **Wi-Fi map (`radio_ui::draw_heatmap`):** a grid of values (signal dBm, speed Mbit/s from `Network::spot_speed`, or a neighbour's signal) worked out a few rows per frame, drawn as one linear-filtered texture, faded outside the walls (the same "walls on four sides" test as the coverage score), with a contour where it turns good. With a device selected it's that device's own map (`heat_focus`). Signal shows the strongest band as measured; the coverage score (`best_rssi`) still counts 2.4 GHz 6 dB lower.
  - **Widgets:** shared ones are in `ui_kit.rs`.

Key cross-file facts:

- **Problem list:** `Network::check()` (net.rs) calls `check_more()` (issues.rs) and produces `Issue`s, optionally carrying a `Fix`. The UI caches the result in `App.issues`. Any edit that changes the plan must reset it (`snapshot()` does this, and also pushes the undo state, capped at 40).
- **Save format:** `.netplan` is `serde_json` of `Network`. `#[serde(default)]` on the structs keeps older files loading, so new fields need a sensible `Default`. Runtime-only fields use `#[serde(skip)]`. Loaded files go through `Network::sanitize()`. An autosave goes every 30 s to `$XDG_CONFIG_HOME` (see `extras::library_path`), next to the device-model library, but only after the plan changed (`autosave_last` starts as the start-up plan, so "Recover last session" survives a restart). `Network::from_json` only accepts JSON with a `devices` list. Unsaved changes are `plan_hash(net) != saved_hash`; closing asks first. Undo steps carry the file they belong to. Floor-plan pictures are stored inside the plan (`FloorPlan::data`, JPEG base64); old saves fall back to `path`. Recent plans are in `recent.json` beside `settings.json`.
- **Templates:** `net::template(key)` / `template_seeded(key, seed)` build the ready-made plans. The scenario keys and menu text are in `scenarios.rs` (`SCENARIOS`, `build`). Tests usually start from a template, e.g. `template("flat")`.
- **Reproducible randomness:** each plan has a `seed`. `sim.rs` derives MAC addresses, fading and traffic noise from it with a hash, so use `sim::hash` instead of a global RNG.
- **Units:** canvas pixels map to metres via `net::PX_PER_M` (20 px = 1 m). Wi-Fi ranges, cable lengths and coverage area all use it.
- **Phone link:** it starts only when the user presses "Link a phone". It answers a UDP broadcast `NETSKETCH?` on 47879 and serves `GET /plan` / `POST /points` on TCP 47878, plus the phone's Wi-Fi speed test (`GET`/`POST /speed`, stored as `Speed.lan_down_mbps`/`lan_up_mbps`), all guarded by a 4-digit code. The Java side is `companion-android/src/.../Link.java`, so keep the two in sync.
- **Ports (`ports.rs`):** `Device.ports` is a list of `PortGroup`s (count, speed, RJ45/SFP/DSL/coax, WAN flag), saved as `port_groups`. Each `Link` records the port at each end (`a_port`/`b_port`), and a cable's speed comes from those two ports (`end_mbps`, `negotiated`). `assign_ports()` keeps cables where they fit and puts the rest in the best free port, with the internet line on the WAN side and fast devices on fast ports. It runs in `connect`, in `sanitize`, at the end of every template, and every frame in the UI. After a device gets new hardware, call `replug(id)` so its cables re-plug from scratch. Old saves had `ports`/`port_mbps`; `sanitize` turns them into groups, adding the WAN port the old home-router count left out.
- **Product catalog (`catalog.rs`, files in `data/`, embedded with `include_str!`):**
  - `devices.json` holds real routers, mesh nodes, extenders, APs, outdoor bridges and wired gateways: Swisscom's whole lineup, other Swiss providers' boxes and popular brands. The `Product` struct documents each field. `Product::fits` decides which device kinds a product may become: role `home` (ISP boxes, Wi-Fi routers, gateways, firewalls) is for the Home router only, role `router` (general-purpose wired routers) for the plain Router and the Home router.
  - `plans.json` holds Swiss internet plans, which set the internet connection's speed.
  - `powerline.json` holds powerline kits. A powerline link stores its kit in `Link.kit`, which sets the link's speed and its price in the shopping list.
  - `deny_unknown_fields` plus the catalog tests reject bad entries.
  - Pickers: `radio_ui.rs::catalog_picker` (in "Wi-Fi hardware", and in "Hardware" for plain routers), `ui_extras.rs::plan_picker`, and the "Kit" row in the cable panel.
  - This is separate from the user's own saved models (`extras::Model`, `~/.config/netsketch/models.json`).
  - Known Swisscom gaps: Swisscom's download centre also lists older hardware not yet in the catalog, because its specs weren't verified. That covers the WLAN-Booster (2014), the WLAN Dual Band Access Point (an ASUS RT-AC66U), the WLAN-Netzerweiterer (2013), AirTies units (Air4400, Air4742v2, Air4641), wireless TV kits, and the Huawei mobile routers and hotspots of the Mobile Unlimited offer (B315s, B593s, E5776s, E5786s, E5330). Bluewin-era ADSL routers (Netopia 3347W/3357W, Zyxel Prestige) are missing too. Many power, price and year values are estimates, and each entry's note says so.
- **Language (`i18n.rs`):** English text is the key. Wrap interface text in `tr("...")`, and text with values in `trf("... {} ...", &[&value])` (no format specs inside; pre-format numbers). German lives in `data/de.json` and `data/lessons_de.json`; a test checks placeholders match. Model labels (`Kind::label`, `Medium::label`, …) translate themselves through `*_en()` helpers. Templates start in the chosen language (`template_seeded` translates title and story). Terminal output and the packet log stay English.
- **Look and settings:** colours come from `pal()` (the Dark, Light and High contrast palettes in `main.rs`), never fixed constants. `Settings` (theme, text size, language, quiz progress) lives in `settings.json` next to the device library; screenshots always use the defaults.
- **Undo for in-place edits:** an edit that rewrites a device or cable while it is borrowed (catalog pick, preset, cable type, port groups) stores the old copy in `App.before`; the next frame turns it into an undo step (`snapshot_before`).
- **Exercises:** `scenarios::EXERCISES` and `check_exercise` (a goal per scenario, checked against the plan); `Network.scenario` remembers which template a plan came from. Lessons have a quiz each (`lessons::QUIZ`).
- **Traffic (`extras.rs` `loads`):** each device's demands follow their real route and are shared out by max-min fairness, High priority first (`share`). The capacities (`Res`) are one direction of a cable (the internet line's upload side is the plan's upload speed), both directions of a half-duplex link (powerline, mesh), or a radio channel's airtime (`AIR` + band, keyed by `chan_src`, so a single-radio repeater shares its upstream's; a Mbit/s costs 1/rate of it). `Network::demands(d)` is the only way to read what a device asks for: Organic uses `Device.uses` along the time-of-day curve times `Network.traffic`; Custom (`custom_traffic`) uses `Device.test_uses` at full rate plus an own load `Device.test_mbps` to the internet or `test_to`. `loads()` is the long-run average (problems, chart, plans); `loads_now()` is live in Simulate (`want`: page loads on clicks, video in chunks, jitter; Custom only with `custom_bursty`). `settle` shares twice so Wi-Fi contention (`demand_airtime`) follows the airtime really used; that and what bursts got last time live in `Network.memory` (not saved). `utilisation` is what gets through (≤ 1), `wanted` what the apps ask (can pass 1). `day_load()` gives the overview's 24-hour chart. The moving dots and a cable's hover tag in Simulate come from `loads_now` and can be switched off (`Settings.flow`).
- **Radio model (`wifi.rs`):** `path_losses` is multi-wall over 3-D distance plus one bend round a wall end or outside corner (`wall_edges`, knife-edge, capped; cached in `Network.edge_cache`); a clear path passing close to an edge loses up to 6 dB, so the shadow boundary is continuous. Slanted walls follow `slant_path`/`slant_reflect` (refraction, not 1/cos), a repeated wall kind costs 0.85×. Rates follow the 802.11 sensitivity table (`MCS_80`, `sens`). `fading`/`stability` give each link's fading (Nakagami m from line of sight, antennas and width), retries, loss and drops per hour; live links really drop and rejoin (`hold_drop`, `Network.link_down`). Others the access point can't hear (or on the channel next door, `ACR_DB` weaker) talk over what the device receives: for their busy share the rate follows SINR (`colliders`, `Signal.hit`/`hit_cost`), while ones it hears take turns (`heard_load`). Each Wi-Fi name costs beacon airtime (`beacon_share`, `names_sent`). `Network.wall_fit` scales a wall kind's published loss; `learn_walls` (companion.rs) fits it with each own access point's offset from all placed pins. Every constant names its source (ITU-R P.2040/P.1238/P.526, TGn/TGax, WiSe…): change values only with a source.
- **Speed (keep the campus template smooth):** `path_losses` is cached by its exact inputs in `Network.path_cache` (cleared when walls, slab or storey heights change). Grid scans over one-off spots (Wi-Fi map, report, AP suggestion) use the `_raw` variants and `strongest_at`, which skips radios that can't win. The first half of every corner detour is cached per transmitter (`legs_from`). `Network.memo` keeps `signal`, `demand_airtime`, `stability` and `stp` for one UI frame only: the app turns it on and empties it at the start of each frame and in `snapshot()`; `apply_fix`, `roam_step` and `settle` empty it too. Model code and tests run with it off. Copies of a `Network` (undo steps) start with empty caches. The Wi-Fi map is worked out a few rows per frame (`HeatJob`). `cargo test --release campus_speed -- --ignored --nocapture` times a frame, a refresh and the map against budgets.
- **Phone report (`companion.rs`):** besides points, a survey can carry `watch` events (channel changes, roams, drops…), the phone's `findings` and `lan` devices; they are kept in `Network.phone`. Channel-change events mark a device `auto_ch` and feed the auto-channel check (`channel_jumps`); `measured_checks` compares an extender's uplink with what was measured next to it and lists the phone's findings.
- **Software (`soft.rs`):** `Device.installed` lists the `Soft` a device has (`Soft::fits(kind)`, `Soft::defaults`). A server runs when installed and its `services.*` flag is on (`running`, `set_running`); `fit_software()` installs whatever a plan or template switches on. Files live in `Device.files` by path; the web server serves `webserver/`, file sharing lists `shared/`. Mail is stored on the receiving server (`Device.inbox`, saved), sent with the mail program's account (`mail_account`), and refused for names missing from a server's `mailboxes`. A host with the Firewall installed and on applies its `rules` to what it sends and receives, inside `send`.
- **Country rules:** `Network.region` (`wifi::Region`) sets which channels and power limits `Band::channels`, `eirp_limit` and `dfs` use. It's held per thread (`Region::set`): the app sets it every frame, `check()` and the report set it too.
- **Report (`report.rs`):** Export writes one self-contained HTML page (an SVG Wi-Fi map per storey, channels, shopping list, problems, addresses) in the UI language. The coverage target `Network::target` (dBm) drives the score (`plan.rs`), the map colours and the legend (`radio_ui::heat_bands`).
- **Built-in browser:** `html.rs` is a deliberately tiny HTML renderer. `main.rs::fetch_real` fetches real pages with `ureq` (3 MB cap, 15 s timeout). Speed-test sites get an internal test instead.

## Conventions seen in the code

- Every file starts with a `//!` header saying what it covers. Keep it accurate when moving things.
- UI and lesson text is plain English for non-experts, current (no obsolete hubs, IPv6 is normal, WPA3, etc.). Don't reintroduce outdated facts.
- Known simplifications are marked `// shortcut: <limit>` (e.g. the multi-wall path-loss model in `wifi.rs`, the HTML subset in `html.rs`).
- Icons come from `egui_phosphor::regular` (imported as `ic`).
